# Improvement roadmap

Prioritised, sized and sequenced work after the 2026-11-04 audit branch.
Order of precedence: capital protection, then evidence, then supply chain
and local trust, then architecture, then convenience. Every item is a
small, reversible pull request with its own tests; none enables live
trading, changes a strategy parameter or a default silently, or claims a
return. Sizes: S (under a day), M (days), L (a design document first, then
several PRs). "Done when" is the acceptance test, not a promise of profit.

## 0. On this branch (reference)

Twenty-two confirmed defects fixed with regression tests, three new
independent risk controls, the research statistics module and the twelve
audit documents (`IMPLEMENTATION_CHANGELOG.md`, `CRITICAL_DEFECTS.md`).

## 2. Rejected or deferred on purpose

* **Machine learning (brief Phase 5)**: rejected for now. The trade samples
  are hundreds of round trips per strategy, the committed research shows no
  stable edge for a learner to improve on, and 46 variants have already
  read the validation data; a learner fitted on top would be selection on
  selection. Revisit only with R-1's real-data output, a pre-registered
  protocol and an untouched holdout, and only if a reproducible, cost-aware
  improvement appears out of sample.
* **A rewrite, a message bus, a service split or a second process**: the
  operator runs one account on one PC; each would add failure modes with no
  capital benefit (`ARCHITECTURE.md` section 5).
* **Live enablement by any automated step**: stays a manual, phrase-confirmed
  action by the operator after `PRODUCTION_READINESS.md`'s go/no-go list.
